# Test Data

## Sample Input Data

**File:** `sample_input.csv`  
**Records:** 874 records representing ~250 unique entities  
**Purpose:** Testing entity resolution matching algorithms

### Data Characteristics

- **Average records per entity:** 3.5
- **Source systems:** 5 (enrollment, claims, case_management, provider_portal, edi_files)
- **Date range:** 1950-2005
- **Intentional variations:**
  - Exact duplicates (same person, identical data)
  - Name case variations (ROBERT vs Robert)
  - Nicknames (Robert vs Bob, Jennifer vs Jen)
  - Address format differences (Street vs St, Apt vs #)
  - Minor typos (Johnson vs Jonson, Davies vs Daives)
  - Different apartments (same building, different units)

### Schema

```
source_system_id    - Source system identifier
source_record_id    - Unique ID within source system
first_name          - First name (may vary)
middle_name         - Middle name or initial
last_name           - Last name (may have typos)
dob                 - Date of birth (YYYY-MM-DD)
ssn_hash            - SHA-256 hash of SSN
ssn_last4           - Last 4 digits of SSN
address_line1       - Street address
address_line2       - Apartment/unit number
city                - City name
state               - State (MD/Maryland)
zip_code            - ZIP code
phone               - Phone number
email               - Email address
created_date        - Record creation timestamp
updated_date        - Last update timestamp
ingestion_timestamp - When loaded into system
```

### Example: Duplicate Entity

These 4 records represent the same person with variations:

```csv
Jennifer,Johnson,1997-05-08,3757 MAIN ST
JENNIFER,JOHNSON,1997-05-08,3757 MAIN ST
Jen,Johnson,1997-05-08,3757 Main Street
Jenny,Jonson,1997-05-08,3757 Main St
```

**Matching challenge:** Detect these are the same person despite:
- Case differences (Jennifer vs JENNIFER)
- Nickname variations (Jennifer → Jen → Jenny)
- Last name typo (Johnson → Jonson)
- Address formatting (MAIN ST vs Main Street)
